# how-to Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A sourced zsh function `how-to <request>` that asks an LLM for one shell command and pushes it onto the prompt buffer unexecuted.

**Architecture:** One file `src/how-to.zsh` with four parts: output cleaning, context assembly from pluggable `_how_to_context_<name>` functions, pluggable `_how_to_provider_<name>` model providers (default `claude --print`), and the `how-to` entry point that ends in `_how_to_push` (`print -z`). Tests in `src/test.zsh` source the file and stub providers/push.

**Tech Stack:** zsh only (no frameworks, no build). Default provider: Claude Code CLI.

**Spec:** `docs/superpowers/specs/2026-10-10-how-to-design.md`

## Global Constraints

- Layout: all source in `src/` (`src/how-to.zsh`, `src/test.zsh`); docs in `docs/` (`docs/usage.md`); root `README.md` is a one-paragraph summary linking to `docs/usage.md`.
- No dependencies beyond zsh and the provider CLI. No network in tests.
- Provider contract: `_how_to_provider_<name>` — `$1` = system prompt, stdin = user message, stdout = raw response, non-zero exit on failure.
- Context contract: `_how_to_context_<name>` prints zero or more `key: value` lines; failures/missing functions contribute nothing and never abort.
- Defaults set only if unset: `HOW_TO_PROVIDER` (`claude`), `HOW_TO_CONTEXT=(os shell cwd git tools)`, `HOW_TO_TOOLS=(rg fd jq yq tokei cloc fzf bat eza gh docker kubectl brew git python3 node)`.
- Claude provider: `command claude --print --tools "" --no-session-persistence --system-prompt "$1" ${=HOW_TO_CLAUDE_ARGS:---model haiku}`. Never `--bare`.
- Failure marker `HOWTO_FAIL:` is internal; user sees only the reason.
- Error messages/status exactly as the spec's Errors table; all to stderr; buffer untouched on error.
- Internal helpers are prefixed `_how_to_`; locals declared `local` so sourcing leaks nothing but the documented names.

## Review Focus

1. **Glob characters in the request** (`how-to find all *.log files`): zsh globs args before the function runs and errors with "no matches found". Expect the request to arrive verbatim → ship `alias how-to='noglob how-to'` in `src/how-to.zsh` (Task 3 test).
2. **Fenced reply that is a failure** (```` ```\nHOWTO_FAIL: no such thing\n``` ````): expect it treated as failure, not pushed (Task 3 test).
3. **User config set before sourcing** (`HOW_TO_CONTEXT=(os)` in `.zshrc` above the `source` line): expect it preserved, not overwritten (Task 2 test).
4. **Directory with spaces / huge directory / not a git repo**: expect `cwd` context correct, `files:` capped at 30 entries, `git` silent (Task 2 tests).
5. **Quotes and `$` in the request** (`how-to replace "foo" with $bar`): expect passed literally to the provider, never expanded or evaluated (Task 3 test).
